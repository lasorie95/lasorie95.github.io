Recorded Lore의 첫 개발 기록을 남긴다.

이번에는 새로운 프로젝트를 만들고, 앞으로 사용할 개발 환경과 기본 파일 구성을 정리했다. 현재 저장소에는 시작 씬과 최소한의 C# 스크립트가 들어 있다.

첫 일지에서는 어떤 환경으로 프로젝트를 시작했고, 현재 어디까지 준비했는지 기록하려고 한다.

## 개발 환경의 기준 정하기

현재 프로젝트의 개발 환경은 다음과 같다.

| 항목 | 구성 |
|---|---|
| 게임 엔진 | Godot 4.7.2 Mono 커스텀 빌드 |
| 개발 언어 | C# |
| 실행 환경 | .NET 8 |
| SDK | 8.0.403 |
| 편집기 | VS Code |
| 버전 관리 | Git |

.NET SDK 버전은 `global.json`에 명시했다. 다른 버전으로 자동 전환되지 않도록 설정해, 프로젝트에서 사용할 SDK의 기준을 고정했다.

Godot 관련 패키지의 버전은 `packages.lock.json`에 기록하고 있다. 엔진과 C# 프로젝트가 사용하는 패키지 구성을 함께 확인할 수 있도록 준비한 상태다.

VS Code에는 Godot 실행 경로와 C# 빌드 작업을 등록했다. 프로젝트 폴더를 열고 기본 빌드 작업을 실행할 수 있는 구성이다.

## 시작 씬과 C# 스크립트 연결

현재 프로젝트의 주요 구성은 간단하다.

```text
scenes/
└─ Main.tscn

src/
├─ Main.cs
└─ Main.cs.uid
```

`Main.tscn`은 게임을 실행할 때 사용할 시작 씬이다. 현재는 `Node` 하나에 `Main.cs`를 연결해 두었다.

`Main.cs` 역시 `Node`를 상속한 빈 클래스다. 캐릭터 조작이나 전투, 화면 구성 같은 게임 기능은 아직 들어 있지 않다.

현재 진행 상황은 **새 프로젝트의 설정과 시작 씬, C# 코드의 연결 구조를 준비한 단계**라고 정리할 수 있다.

## 빌드 설정과 파일 관리

C# 프로젝트에는 다음 설정을 적용했다.

- Nullable 참조 형식 검사 사용
- 빌드 경고를 오류로 처리
- 의존성 잠금 파일 생성
- 결정적 빌드 옵션 사용

게임 기능이 추가되면 코드와 의존성도 늘어나므로, 초기 설정부터 기준을 남겨두었다.

Git에서는 소스와 프로젝트 설정을 관리하고, Godot 캐시와 빌드 결과물은 제외하도록 구성했다. `.godot`, `bin`, `obj`, `.artifacts` 같은 생성 폴더가 여기에 해당한다.

이 초기 구성을 첫 커밋으로 기록했다.

## 현재 상태

지금까지 저장소에 준비된 내용은 다음과 같다.

- 독립된 프로젝트와 Git 저장소 구성
- Godot와 C# 프로젝트 설정
- .NET SDK 버전 고정
- 빈 시작 씬과 C# 스크립트 연결
- VS Code 빌드 작업 등록
- 생성 파일을 제외하는 Git 관리 설정

초기 프로젝트 가져오기와 시작 실행 로그도 남아 있다. 다만 이것은 개발 환경을 준비하는 과정의 기록이며, 게임 기능이나 플레이 흐름을 검증한 단계는 아니다.

## 다음 단계에서 정할 것

이제는 게임 안에서 어떤 경험을 만들 것인지 구체화할 차례다.

우선 다음 내용을 정리할 필요가 있다.

1. 플레이어가 처음 접하게 될 화면과 상황
2. 가장 먼저 구현하고 확인할 작은 플레이 목표
3. 그 목표에 필요한 최소한의 규칙과 기능

이번 기록은 Recorded Lore의 출발점을 남기는 일지다. 이후에는 실제로 추가한 기능과 동작을 확인한 결과를 중심으로 개발 과정을 이어가려고 한다.
