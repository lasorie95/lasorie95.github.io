# Lasorie RPG World — 블로그 설계

작성일: 2026-10-14 (Asia/Seoul)

## 2. 첫 화면과 탐색 구조

한국어 메뉴와 밝은 배경, 차분한 파란색 포인트를 사용한다. 본문은 읽기 쉬운 너비로 표시하고, 프로젝트 목록은 카드 형태로 구성한다. 작은 화면에서는 메뉴와 콘텐츠가 화면 너비에 맞게 배치된다.

| 메뉴 | 경로 | 내용 |
| --- | --- | --- |
| 홈 | `/` | 블로그 소개, 최신 글, 대표 프로젝트 |
| 개발·공부 기록 | `/posts/` | 최신순 글 목록, 카테고리와 태그 안내 |
| 카테고리 | `/categories/` | 분야별 글 모음 |
| 태그 | `/tags/` | 주제별 글 모음 |
| 프로젝트 | `/projects/` | 프로젝트 카드 목록 |
| 프로젝트 상세 | `/projects/project-rpg/` | Project RPG 소개와 도구·역할 |
| 소개 | `/about/` | 제공받은 소개 문구, 관심 분야, 공개 GitHub 프로필 링크 |

상단 주요 메뉴에는 개발·공부 기록, 프로젝트, 소개를 배치한다. 홈은 사이트 이름으로 이동한다. 카테고리·태그는 글 목록에서 접근한다. 테마의 사이트 검색을 활성화한다.

아직 첫 글의 내용은 제공되지 않았으므로 글 목록은 빈 상태를 지원한다. 공개되지 않은 학습 활동이나 성과를 실제 기록처럼 만들어 넣지 않는다. 첫 글이 등록되면 해당 카테고리·태그와 최신 글 목록에 반영된다.

표시할 관심 분야는 사용자 문구를 유지하며, 글의 실제 카테고리와 태그는 각 글에서 지정한다.

## 3. Project RPG 포트폴리오

프로젝트에 사용할 확정 정보:

- 표시 이름: **Project RPG**
- 설명: **1인 제작 PC용 2D RPG 프로젝트. 최종 게임 이름은 미정입니다.**
- 사용 도구: **Godot, VS Code, Git, Aseprite**
- 역할: **1인 개발**
- 저장소 후보 주소: `https://github.com/lasorie95/project_rpg`
- 저장소 상태: 사용자 설명에 따르면 현재 Private이며 추후 Public 전환 예정

프로젝트 카드와 상세 페이지에는 위 정보를 표시한다. 진행 상태, 진행률, 출시일, 구현한 기능, 사용한 Godot 버전, C# 사용 여부, 성과는 제공되지 않았으므로 사실로 추가하지 않는다. C#은 블로그의 관심 분야이며 프로젝트의 실제 구현 언어로 단정하지 않는다.

프로젝트 저장소가 공개되어 누구나 접근할 수 있음이 확인되기 전에는 방문자를 비공개 저장소로 보내는 버튼을 활성화하지 않는다. 이때는 `프로젝트 저장소 공개 준비 중` 안내를 사용한다. 블로그 작업 과정에서 프로젝트 저장소의 공개 설정을 변경하거나 비공개 소스를 가져오지 않는다. 공개가 확인되면 프로젝트 문서의 링크 설정을 변경할 수 있도록 한다.

이미지는 제공된 것이 없어 처음에는 텍스트 카드로 구성한다. 나중에 사용자가 제공하는 실제 게임 화면을 카드와 상세 페이지에 추가할 수 있게 한다.

## 4. 제작과 게시 방식

### 구성

- **Jekyll + Minimal Mistakes remote theme**를 사용한다.
- 테마 버전은 공식 시작 문서에서 안내하는 `mmistakes/minimal-mistakes@4.28.1`로 고정한다.
- 언어는 한국어, 시간대는 `Asia/Seoul`, 사이트 주소는 `https://lasorie95.github.io`, `baseurl`은 빈 문자열로 설정한다.
- 테마가 요구하는 `jekyll-include-cache`와 GitHub Pages 지원 플러그인을 확인해 구성한다.
- 글은 `_posts/`의 Markdown 파일, 프로젝트는 `_projects/`의 Jekyll collection으로 관리한다.
- 탐색 메뉴는 `_data/navigation.yml`에, 글과 페이지의 기본값은 `_config.yml`에 설정한다.
- 테마의 글 상세 레이아웃, 코드 강조, 검색, 사이트맵과 RSS 기능을 활용한다.

### 데이터 흐름

작성자가 Markdown 파일에 글이나 프로젝트 정보를 작성한다. 저장소에 반영되면 GitHub Pages의 Jekyll 빌드가 글·메뉴·프로젝트를 HTML로 생성하고 정적 사이트로 게시한다. 별도의 서버나 데이터베이스는 사용하지 않는다.

기존 GitHub Pages의 게시 원본을 확인한 뒤 `main` 브랜치의 저장소 루트에서 Jekyll로 빌드하도록 구성한다. 현재 게시된 12줄짜리 `Hello, World!` 초기 화면은 블로그 홈으로 교체한다. 기존 저장소와 커밋 기록은 유지한다.

### 공개 범위

사용자가 제공한 소개, 관심 분야, 프로젝트 개요와 블로그 글을 공개한다. 제공되지 않은 연락처는 공개 페이지에 넣지 않는다. 과거에 로그인 정보로 전달된 이메일을 공개 연락처로 사용하지 않는다.

설계 문서, 개발용 파일, 의존성 파일 등은 블로그 빌드 결과에서 제외한다. 이는 블로그 화면에 표시하지 않는다는 뜻이며, Public 저장소에 반영된 원본 파일은 GitHub에서 공개된다. 댓글이나 방문 통계를 원할 때는 해당 서비스의 설정을 별도로 추가할 수 있게 한다.

## 5. 운영과 오류 처리

- 새 글을 작성하는 파일명, 글 정보, 카테고리·태그, 이미지 경로를 README에 한국어로 설명한다.
- 프로젝트를 추가·수정하고 저장소 공개 후 링크를 활성화하는 방법도 README에 안내한다.
- 글이 없을 때는 명확한 빈 상태를 표시하며 존재하지 않는 글 링크를 만들지 않는다.
- 이미지가 없는 프로젝트는 텍스트 카드로 정상 표시한다.
- 빌드 오류가 발생하면 GitHub Pages 빌드 결과를 확인하고 원인을 수정한 뒤 다시 게시한다.
- 사용자 정보와 원격 변경 상태를 확인한 후 작업 브랜치에서 변경을 준비한다. 게시하는 정확한 소스를 검증하고 기록한다.

## 6. 완료 확인 기준

1. Jekyll 빌드가 성공하고 테마·플러그인 관련 오류가 없다.
2. 사이트 이름, 작성자와 소개 문구가 제공한 내용대로 표시된다.
3. 홈, 글 목록, 카테고리, 태그, 프로젝트 목록, Project RPG 상세, 소개 페이지를 방문할 수 있다.
4. 검색이 실제 공개된 콘텐츠를 대상으로 작동한다. 첫 글이 없는 상태도 정상 표시된다.
5. PC와 모바일에서 메뉴, 본문, 프로젝트 카드가 겹치거나 화면 밖으로 넘치지 않는다.
6. 프로젝트의 설명·도구·역할에 제공하지 않은 사실이 추가되지 않는다.
7. 프로젝트 저장소가 비공개인 동안 공개 GitHub 버튼을 활성화하지 않는다.
8. 연락처 미제공 상태에서 로그인 이메일이나 개인 연락처가 공개되지 않는다.
9. 글·프로젝트 작성 방법이 README에 정리되어 있다.
10. 자동 게시가 완료된 뒤 실제 블로그 주소에서 최신 결과와 주요 링크를 확인한다.
